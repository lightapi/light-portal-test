# ROLE ask fixture driver

`make workflow-role-contract` checks the versioned `human-approval.yaml` ROLE assignment and the fail-closed MCP receipt parser. It creates no Portal or Workflow state. `make workflow-role-runtime` is the later Step 10 Gateway gate; it requires the additive `workflow_start`, role tools and terminal delete to be published and callable. Contract mode is never runtime evidence.

Runtime requires `WORKFLOW_ROLE_CONTEXT_FILE` pointing to a private JSON file with `hostId`, prepared `workflowDefinitionId`, `stableToolRef`, `expectedDefinitionDigest`, `gatewayUrl` (`https://localhost/mcp`), `portalCommandUrl` (`https://localhost/portal/command`), `memberBUserId`, `fixtureOwnedMembership: true`, and file paths `authorTokenFile`, `memberATokenFile`, `memberBTokenFile`, `nonmemberTokenFile`, `adminTokenFile`. Obtain saved-definition preparation, dedicated disposable users and bearer-token files through the documented local stack and login/fixture helpers. Do not put token values in JSON, source, evidence or logs. Configure the local CA for Node before running (for example through `NODE_EXTRA_CA_CERTS`). The nonmember must have the human-task Tool ACL so the gate tests Workflow assignment denial, not only Gateway discovery denial.

The driver starts the real ROLE `human-approval.yaml` through Gateway MCP, checks summary/list/detail and two-member claim race, revokes one fixture-owned role membership through the Portal `deleteRoleUser` command, checks denial with the same token and no continuation, restores that membership through `createRoleUser`, releases/reclaims/completes, checks terminal continuation, and requests terminal deletion. **Authorization amendment, September 25:** this same-token revocation assertion reflects the superseded issuer lookup design. Do not run or cite this driver as the current ROLE gate until it obtains a newly issued acting-user token after membership change and verifies Gateway ACL/token forwarding. It never writes Portal projections or resets shared databases. On failure after start it attempts cancellation; the failure includes the sanitized fixture process/instance ID in the evidence only if evidence writing reached completion. A missing context, command permission, credential, binding, route, authority or cleanup version fails the live gate.

Step 02 PostgreSQL component tests use isolated test schema/temporary authority tables; they do not qualify this Gateway driver. Step 10 must run this driver against the local stack and record real sanitized evidence and active build/snapshot IDs.
